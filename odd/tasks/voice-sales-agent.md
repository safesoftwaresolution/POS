# Voice sales agent
Conversational voice/text assistant (Gastroflow-style tool loop, Spring AI) that edits the POS ticket in place; the cashier confirms inline before the sale is registered. Branch: feature/voice-sales-agent. Delivery: ask-on-risk; no commit or publication without explicit approval (project CLAUDE.md). Runner: Java 21, backend `.\mvnw.cmd` (offline); frontend Vitest + oxlint.
Engram mirror (`odd/voice-sales-agent/tasks`): pending (engram MCP failed to connect this session).

## Specs
S1. "quiero que ese asistente pueda funcionar como en gastroflow, mejorarlo mucho parametrizarlo con spring ai, hacer un arnes pero entonces que funcione". Gastroflow reference (`Gastroflow/services/Tenant/Asistente`): bounded model↔tool loop, tools defined server-side, model never receives tenant/user/permissions, writes are only proposed and wait for confirmation, audit trail.
S2. "se dice has una factura con tal y tal producto con tanto plata y el metodo de pago, por defecto dejas el consumidofr final o el cliente general que existe en el sistema". Customer defaults to the store's existing "Cliente General"/consumidor final unless another one is dictated.
S3. "todo se agrege al apartado defactura no que salga un modal de ticket como en la pantalla se muestra no que sea en un modal todo mal visto". The dictated items, customer, payment method and cash land directly in the "Ticket de Venta" panel (CartPanel). No `VoiceDraftModal`.
S4. "que al final salga como que una confirmacion para hacer el pago o registrar la venta me entiendes, obviamente una confirmacion por que puede que se equivoque y demas". Inline confirmation in the panel before registering the sale; nothing is registered, no stock moves, until the cashier confirms. The agent has no tool that registers a sale.
S5. "con lo de hazme una factura me refiero a una factura normal, que no este ligada a la factura electronica solo factura normal la que quedan dentro del sistema". "Factura" = normal sale recorded in the system. The voice flow never sends `sendElectronicInvoice=true`.
S6. Spring AI (2.0.x, supports Boot 4.0/4.1) behind a configurable provider/model (`spring.ai.*` + `voice-sales.agent.*`); the feature stays disabled by default and the manual POS keeps working if the provider fails (from voice-sales-preview S11).
S7. The harness is deterministic: a scripted `ChatModel` drives the real tool loop in tests (offline, no key); an opt-in live evaluation of Spanish utterances runs only when `GROQ_API_KEY` is set.
S8. Prices, totals, tax and identifiers never come from the model; the server resolves catalog/customers of the authenticated store via facades (voice-sales-preview S9, S10, S12 still hold).

Config: `voice-sales.agent.enabled` (false by default, true in dev), own quota (30/min user, 120/min store).
